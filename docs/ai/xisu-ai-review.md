## 一、模型覆盖与筛选体验

犀速AI的模型目录按供应商、可用性、端点和输入单价筛选，常用分类包括 Claude、GPT、Gemini 和 Grok。文本模型覆盖 Claude 系列、GPT-5.5、GPT-5.6 变体、Gemini 3.7/3.8 Flash High 以及 Grok 4.6/4.7；图像能力则提供 `gpt-image-2.5-sunburst` 一类生图模型，并按分辨率和质量区分单次生成价格。

从使用效率看，按供应商筛选比在多个站点之间切换更省时间。写作任务可以快速比较 Claude、GPT 和 Gemini，代码任务可以直接筛选 Codex 或 GPT 系列，实时信息和风格化问答则可以切换 Grok。模型数量会随平台上架、下架和版本调整变化，正式使用前仍要打开模型详情，确认上下文长度、最大输出、视觉能力和工具调用支持。

这类聚合平台的优势是选择集中，风险是模型名称不一定完全等同于官方版本。建议把模型名称、接口类型和计费单价一起记录，不要只根据“GPT”“Claude”或“Gemini”等品牌标签判断实际能力。

## 二、国内网络直接使用 Codex 与 Gemini

犀速AI的核心卖点是国内网络环境下可以直接使用 Codex、Gemini，不需要额外配置翻墙工具。对国内用户而言，这能减少网络环境、账号注册和模型切换带来的使用门槛，尤其适合日常代码辅助、文档总结、资料问答和 Gemini 多模态任务。

实际使用时，Codex 更适合代码阅读、重构、报错分析和开发辅助；Gemini 可用于长文本整理、多模态内容理解和日常问答。建议先用同一组任务测试首字延迟、完整响应时间、上下文连续性和错误率，再判断哪个模型适合作为主力。国内直连并不代表所有模型、所有地区和所有时段都永久可用，模型状态应以犀速AI当前公告和控制台为准。

如果你的主要需求是写作、翻译、总结等任务，可以先用低输入价格的文本模型；代码和复杂推理则应重点比较输出准确率、上下文长度和响应稳定性；图片任务要单独查看 OpenAI Images 端点支持的分辨率、质量和单次扣费。

开发者还可以利用不同端点区分接入方式。OpenAI 兼容接口适合已有 SDK 或聊天应用，OpenAI Responses 适合需要新式响应结构、工具调用或多模态能力的项目，Anthropic 端点则适合已有 Claude API 调用代码的用户。平台标注“支持接口”不等于所有参数完全一致，正式接入前应先用最小测试请求确认鉴权、流式输出、错误码和上下文传递。

## 三、价格与 Token 成本评测

犀速AI按每 100 万 Token 展示输入、输出、缓存读取和缓存写入等价格，并提供约 0—5、5—20、20 以上的单价区间筛选。这个设计适合快速找低价模型，但页面单价不等于一次任务的最终成本。长上下文、长输出、批量请求和图片任务，都可能让实际扣费明显高于短问答。

建议先建立一个小型测试表：同一段中文长文交给一个 Claude、一个 GPT、一个 Gemini；同一段代码交给两个代码模型；再用一个图像模型生成同样的提示词。记录首字延迟、完整响应时间、错误率、输出质量和扣费金额。这样得到的是自己的实际单位成本，比只看页面上的倍率或“首月优惠”更可靠。

## 四、充值和 API 使用前的核查清单

第一，确认模型名称、版本、上下文和价格页面是否一致，避免把供应商标签当成官方授权证明。第二，先小额充值或使用平台提供的测试能力，确认余额扣费和错误重试符合预期。第三，检查 API Key 是否可以撤销、是否能设置额度，以及平台是否说明请求日志的保存方式。第四，不要上传身份证、客户名单、未公开代码、合同或财务资料，尤其不要把敏感内容用于未核实的数据中转服务。

如果平台同时提供网页端和 API，建议分开记录用途与密钥。生产应用应设置每日预算、超时、重试和模型降级策略；个人测试则可以固定一个低价模型作为默认，再保留一个高质量模型处理复杂任务。遇到模型突然不可用，先检查公告、余额、端点和请求格式，不要连续生成大量请求。
