## 重点评测项目

### 1. 倍率是否透明

看到“x0.01”“x0.4”等标签时，需要确认倍率对应输入、输出还是总 Token，也要确认是否有最低消费、长上下文附加费、图片费用和高峰期调整。最简单的办法是使用相同长度的测试文本，记录调用前后的余额变化，再计算每次任务的真实成本。

### 2. 模型分组是否准确

同一个大类可能包含基础模型、增强模型、推理模型和兼容模型。使用 Claude、GPT、DeepSeek 或 Gemini 时，要核对上下文、工具调用、视觉输入和知识更新时间。生图模型还要确认分辨率、排队时间、版权政策和输出保存期限。

### 3. 供应商切换与故障恢复

多供应商是优势，也带来稳定性差异。建议分别测试白天、晚间和周末，观察首字延迟、响应完整度、错误提示和限流情况。重要项目不要只依赖一个模型，最好准备同类备用模型，并在代码中设置超时和重试上限。

### 4. API 与网页端体验

开发者应确认是否兼容 OpenAI API 格式，是否支持流式输出、函数调用、结构化输出和日志查看。普通用户则可以关注历史记录、模型切换、文件上传和长对话是否容易中断。网页端好用，不代表 API 一定兼容，二者要分开测试。
