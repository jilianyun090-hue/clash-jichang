# 免费机场、公益机场和 GitHub 节点列表，先看来源再导入

搜索“免费机场”“公益机场”“机场推荐 GitHub”或“机场推荐 Clash”，会遇到三类东西：软件项目、可导入的订阅文件、以及收集第三方节点的列表。它们不是同一种服务。**Clash 类客户端是工具，节点和线路由服务方提供**；一个仓库里有配置文件，也不代表节点长期可用或值得信任。本文不发布未核实的免费订阅，而是给出判断来源和使用范围的方法。

| :--- | :--- | :--- |

这些词之间有交集，但不值得每个词单独做一篇换标题的文章。更实用的做法是按“免费试用、仓库核查、订阅导入、长期选购”四步处理。已有预算与选购需求的读者，可直接转到[便宜机场推荐](/airport/cheap-airport.html)和[机场总览](/airport/)；这里只讨论公开来源的核查方法。

## GitHub 上要检查什么？

首先看仓库究竟存放代码、文档还是未经解释的订阅 URL。软件仓库应能找到项目说明、发行版本与维护信息；只有一条不停变化的链接，无法证明节点来源。其次核对近期提交和问题区，看看是否存在大量“连接失败”“订阅被劫持”的反馈。再次查看许可证、配置示例和脚本所需权限，不要运行要求管理员权限却不说明原因的安装脚本。

下载客户端时，优先沿着项目官方仓库或发布页进入，不要因为搜索结果标题写着“Clash 免费机场大全”就安装打包好的陌生可执行文件。公开订阅文件还可能包含远程规则与更新地址；导入前至少确认来源、是否要求登录，以及是否会修改系统代理。客户端和订阅的区别、常见格式，可参阅[全平台客户端汇总](/airport/software.html)与[订阅导入指南](/airport/subscription-guide.html)。

如果仓库声称“每日更新”，还应看它究竟更新了节点，还是仅由机器人改动时间戳；两者不同。截图里的“今日可用”也可能只代表发布者自己的网络。出现短链接或多层跳转时，先确认最终地址属于哪个服务，避免误把广告页面、钓鱼登录框当成订阅入口。可以保存项目名称和查看日期，日后失效时才知道应向谁反馈。

## 免费节点适合做什么，不适合做什么？

试用或临时查看公开资料时，可以短时间测试延迟、连接成功率和实际可用性。不要把来源不明的共享节点当成工作主线，也不要用它传输重要账号、支付信息或公司资料。公开节点的使用者可能很多；今天能连上，不代表晚高峰仍可用。是否记录流量、由谁维护、何时删除，也常常无从核实。

评估一个免费方案时，记录“来源、试用期限、流量、节点地区、支持渠道、隐私说明”六项。如果任何一项完全找不到，先停下来核对。真正需要长期稳定连接，可以用月付或试用套餐验证，再决定是否续费；也应准备备用连接，避免单一服务失效时连支持页面都打不开。具体做法见[备用机场策略](/proxy/backup-airport-guide.html)。

## 导入后怎样判断是否合适？

别只看客户端里的绿色延迟数字。分别在日常网页、视频和需要的应用上试用，记录连接成功率与高峰期表现；切换网络后再测一次。若某个节点能打开普通网站，却不能访问目标服务，先查节点地区和服务限制，不能直接认定客户端坏了。订阅更新失败时先检查到期时间和格式，再考虑更换来源。
